# 0008 — The embedded default face is a freestanding generated data module outside the bundle

**Status**: Accepted
**Date**: 2026-09-21 (decided 0.4.9; recorded at 0.9.0)

## Context

A target with no font on disk — the agnos kernel at boot — needs a face to open, and it
consumes kashi's `src/font_data.cyr` the same way: a stdlib-free file taken by path.

## Decision

`fonts/face_data.cyr` is generated by `scripts/face2cyr.py` from an unmodified
LiberationSans-Regular.ttf (OFL 1.1; the licence file travels with the bytes), freestanding (no
stdlib, no heap, no syscalls), stored as 101 string literals of 4,096 bytes, and consumed by
path: `[deps.rekha] modules = ["fonts/face_data.cyr"]`. It is deliberately not in
`[lib].modules` — 1.6 MB of generated literals must never ride into `dist/rekha.cyr` — and it
lives outside `src/` because cyrfmt refuses files over 1,028 KB. Its ten `rekha_face_default_*`
accessors are part of the frozen surface (`docs/api/open.md`).

## Consequences

- **Positive** — a kernel gets a real face with one include and no dependencies.
- **Negative** — the consumer must call `rekha_face_default_verify` after `_copy` before
  exposing the bytes: that FNV-1a check found the cyrius 6.6.3 defect in ≥ 64 KB string literals
  and is the only thing that would find the next one.
- **Neutral** — CI regenerates the module and requires byte identity with the committed one.

## Alternatives considered

- **Ship the face inside the bundle**: 1.6 MB in every consumer. Rejected.
- **One 410 KB literal**: the 6.6.3 defect. Chunks stay even after the fix.
