# 0007 — FreeType 2.14.3's classic interpreter is the hinting oracle, reached through `ctypes`

**Status**: Accepted
**Date**: 2026-09-21 (decided 0.8.1; recorded at 0.9.0)

## Context

0.8.0 measured the interpreter against `scripts/hint_vectors.py`, a second interpreter derived
from the specification in Python — and two interpreters written from one spec share its
misreadings (CHANGELOG 0.8.0 / 0.8.1). The glyph a consumer expects is the one FreeType draws.

## Decision

The reference is FreeType 2.14.3's classic interpreter (`GETINFO` version 35), non-pedantic,
grayscale, square pixels, `FT_LOAD_NO_AUTOHINT`, the size set once per (face, ppem) the way a
consumer drives it — the library on the development host, bound through `ctypes` by
`scripts/ftshim.py` with no freetype-py and no fontTools. `ftshim.py` refuses any other
major.minor: 2.13.2 differs in move arithmetic, `ODD` / `EVEN`, the stack margin and `DELTAP`'s
pop discipline. Every unit program is also loaded under `FT_LOAD_PEDANTIC`, so "rekha agrees"
is never "rekha agrees with a skip". The departures rekha keeps from FreeType are enumerated in
`src/hint.cyr`'s header and pinned in the roadmap.

## Consequences

- **Positive** — 233 rows / 5,372 points of FreeType's own hinted outlines reproduced point for
  point; 26,200 loads of the whole face and 5.4 M loads across 215 host faces with 0 differing.
- **Negative** — the sweeps are dev-host one-offs: CI's Ubuntu carries FreeType 2.13.2, so the
  generated oracle modules (`programs/hint_unit_vectors.cyr`, `programs/hint_glyph_vectors.cyr`)
  are transcriptions regenerated by hand on a 2.14.x host, never in CI.
- **Neutral** — FreeType's sources are read per session and never copied into rekha; a comment
  cites `ref2143/<file>:<line>`, never the text.

## Alternatives considered

- **A second hand-written interpreter as the oracle**: shares the spec's misreadings. Rejected
  after 0.8.0.
- **freetype-py / fontTools**: extra dependencies, and fontTools has no interpreter. Rejected.
